# 蒸馏报告模板

报告文件名：`YYYY-MM-DD_书名.md`（书名取中文全名）。全文中文，结构固定，顺序如下。

## 0. 头部（元信息块）

```markdown
# 读书蒸馏 ·《书名》

作者 / 出版社 / 出版年｜微信读书推荐值 **X.X**（N 人评价：好评 x / 一般 y / 差评 z，深度读者 n）｜YYYY-MM-DD 抽取

> **数据来源**：微信读书 Agent API 实时抓取。书架 N 本，已读完 M 本，已蒸馏 K 本，本次从剩余 P 本非网文中按日期种子随机抽取（bookId xxx）。热门划线为全书读者划线聚合（该接口暂无法按本人账号过滤）。
```

降级模式时来源行改为："降级模式（weread 接口不可用），从公共书单按日期取模抽取，非本人书架数据。"

## 1. 一句话蒸馏

一段加粗的核心判断。要求：
- **反通行叙事**：不写"这本书讲了什么"，写"这本书真正说明的是什么"，且要与最常见的大众读法拉开距离（例：苏轼传不是"天才被小人陷害"，而是"专业判断过硬、政治表达拙劣的人在两极化评价体系里被两边同时判负"）。
- 一句话内完成，但要包含"人/事 + 机制 + 后果"三要素。

## 2. 热门划线透视

1. 列出按热度排序的前 5-6 条划线（引文 + 划线人数）。
2. 归层解读：给这些划线分层（如"安慰功能 / 方法干货 / 人格判断"），指出**划线分布本身说明了读者的真实关切**，再指出"读者真正该看但没划的地方"。

## 3. 思维导图

mermaid mindmap 代码块，root 为书名+作者，8-10 个主枝，按书的时间骨架或论证骨架展开，每枝 3-4 个叶子。节点文字必须短（≤10 字），语法必须是合法 mermaid mindmap（注意括号、逗号会破坏语法，用空格替代）。

## 4. 核心概念精读（5 条，报告的心脏）

每条三级结构：

```markdown
### N. 小标题（书中事实 + 机制名）

【书中事实】2-4 句，含具体数字、人名、时间——必须从书的内容中来，不得泛泛。

【机制提炼】这个事实背后的通用机制，1-2 句。

**蒸馏要义**：这条机制本身推得出什么判断，落到可执行的判断标准；不联结读者个人工作。
```

蒸馏要义写法：
- 写"这条机制本身推得出什么判断"：书内命题的延伸、跨领域同类机制、或它失效的边界条件。
- **硬规则（2026-11-07 用户指定）：不与用户的个人工作联结。** 不得提到申报材料、专精特新、评审判断、客户咨询，不得把书读成工作的注脚。只有用户当次明确要求"结合我的工作"，才做联结。
- 判据：把这段话抽出来、不提读者身份，仍然成立且有用，才合格。
- 好的要义是"判断标准"或"动作序列"（例："顺序不能反：降固定成本→恢复自给→重建叙事"），坏的要义是"要重视XX"这类空话，或"这对你的工作意味着XX"这类嫁接。
- 交付前按 `SKILL.md` 第 4 步的八问自检过一遍**报告自身**（强势批判检验）。

## 5. 关键问答（3-5 组）

用书中内容回答"用户站在自己立场最可能问这本书的问题"。Q 要具体（不写"这本书的核心观点是什么"），A 要引用书中的具体事实/数据兜底。

## 6. 延伸推荐

若已安装 `book-knowledge-graph` 技能，按其规则生成三层推荐（L1=4 直接续读 / L2=2 话题延伸 / L3=1 更远背景），每本必须写出关联句（"A 书的 X 论点回答 B 书的 Y 问题"），至少一本反向书，强度自评（强/中/弱），弱的删。
无该技能时省略本节，不得用主题词联想凑数。

## 7. 总评

三行以内：什么时候读 / 什么时候跳过 / 适合带着什么问题读。
